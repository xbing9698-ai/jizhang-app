# 我的记账

日常快速记录收支，每月合并**支付宝**和**微信**账单，查看花销、分类和交易明细。

- 纯前端网页 App（PWA），可加到手机主屏当图标用
- **数据全程在你手机本地处理，一个字节都不上传任何服务器**
- 每月导入一次账单做复盘，不需要后台实时监控

**在线体验**：https://xbing9698-ai.github.io/jizhang-app/

### 主要功能
- **导入合并**：支持支付宝交易流水 CSV、记账本明细 CSV、微信 xlsx 和通用 CSV，自动识别格式并跳过重复导入
- **自动分类**：约 90% 账单自动归类；手动改一次，系统记住该商户，以后自动归
- **概览仪表盘**：按本账期、自定义日期或全部时间统计收支结余；本账期支持上一账期环比、分类占比、分类下钻、大额支出 Top5、每日趋势和历史账期汇总
- **明细管理**：关键词搜索（商户/备注/金额/分类）、来源/分类筛选、整行可点击的交易列表及商户汇总，详情可改分类，支持四种时间/原始金额排序
- **数据备份**：一键导出/导入 JSON，换设备或清缓存不丢
- **记一笔**：首页直接打开分类宫格和数字键盘，快速记录日常支出与收入，支持删除输错的手动记录
- **资产快照与核对**：记录总资产、总负债、净资产；用两条快照和指定范围的收支辅助核对差额
- **导入对账**：提示手动与导入记录的疑似重复，人工确认或否定；确认后保留明细并可撤销

## 每月怎么用（核心流程）

1. 从支付宝导出 `.csv`、从微信导出 `.xlsx`（见下方导出步骤）
2. 打开 App → 进入「导入」页 → 选择这两个文件（可一次多选）
3. 自动回到「概览」页：看当前所选账期收支、环比、分类占比、每日趋势及大额支出
4. 点概览里任一分类 → 下钻到「按商户汇总」，看清这类钱给了哪些商户
5. 进「明细」页：搜索查账，把高亮的「其他」项手动归类——**改一次，系统记住这个商户，以后自动归**
6.（可选）「导入」页点「导出备份」存一份 JSON，换设备或清缓存后可恢复

## 怎么导出账单

> 各 App 版本菜单位置可能略有变化，以下为大致路径，找不到时搜索"交易流水/账单下载"。

### 支付宝（导出 CSV）
1. 我的 → 账单 → 右上角「…」或「开具交易流水证明」
2. 选「用于个人对账」（不是打印版）
3. 选时间范围 → 发送到邮箱 → 下载得到 `.csv` 文件
4. 注意：支付宝 CSV 是 **GBK 编码**，本 App 已自动处理，无需你转码

也支持支付宝「记账本明细」CSV：真正表头包含「记录时间、分类、收支类型、金额、备注、账户、来源、标签」，表头前的说明行会自动跳过。UTF-8 和 GBK 均自动解码。记账本的「来源」和「标签」保留为原始信息，没有商户字段时交易对方留空。

### 导入身份与重复判断

- 有可靠订单号：内部 ID 为 `order:v1:<平台编码>:<外部订单号编码>`，微信与支付宝使用不同平台前缀；原订单号另存为 `externalOrderId`。
- 没有订单号：内部 ID 为 `file:v1:<平台编码>:<文件内容 SHA-256>:<从 0 开始的数据行序号>`；同一文件内相同行也各自保留。
- 完全相同文件再次导入（包括重命名）按稳定 ID 跳过；有订单号的交易跨文件按平台和订单号跳过。旧记录保留原 ID，并按平台和原订单号兼容比较。
- 无订单号记录不按时间、金额或备注跨文件去重。不同内容的导出文件，即使有相同行也保留，因此重叠导出可能重复计入。
- 纯逻辑归一化没有文件上下文时，用排序后的完整原始行内容加行序号生成可重复的 `row:v1:` ID；应用导入始终使用文件 SHA-256 方案。

IndexedDB v2 仅新增 `snapshots` 表，原交易和商户记忆表不删除、不清空，不修改旧交易 ID 或已有分类。新增字段允许旧记录缺失；备份为 `{ txns, mem, snapshots }`，仍能恢复旧版 `{ txns, mem }`。

### 通用 CSV

在「导入」页下载只有表头的模板，填写后通过同一个账单入口导入：

```text
日期,金额,收支,分类,说明,来源,外部ID
```

日期、金额、收支、来源四列及值必填；分类、说明、外部ID列可省略或留空。日期支持 `YYYY-MM-DD`、`YYYY-MM-DD HH:mm[:ss]`（也接受 `T` 分隔），按本地日期保存，不作时区转换。金额必须大于0，最多两位小数；收支只能为「支出 / 收入」。格式或任意数据行无效时明确报错，本次文件不部分导入。

来源保留实际名称，如拼多多、招商银行、Google Play、现金；「手动」是记一笔的保留来源，通用导入不能使用。填写的分类原样保留并受保护，留空时沿用规则或归「其他」。说明用于显示和搜索，交易对方留空，不把说明猜成商户。

有外部ID时沿用「来源 + 外部ID」稳定身份；无外部ID时沿用「文件内容SHA-256 + 来源 + 行序号」。同文件改名仍跳过；不同文件仅日期金额相同不会自动去重。

### 微信（导出 xlsx）
1. 我 → 服务 → 钱包 → 账单 → 右上角「常见问题」→「下载账单」
2. 选「用于个人对账」→ 选时间范围 → 填邮箱
3. 邮箱收到一个**加密压缩包**，解压密码会通过**微信支付公众号的消息**发给你
4. 用该密码解压，得到 `.xlsx` 文件，再导入本 App

## 固定账期说明

账期为上月15日～本月14日，按结束月命名。例如选择 `2026-10`，统计范围为 `2026-09-15 ～ 2026-10-14`；14日23:59:59仍属本账期，15日00:00:00归入下一结束月。

默认显示今天所在的账期：14日仍属本月结束的账期，15日起归入次月结束的账期。例如10月13日默认2026-10，10月15日默认2026-11。可选择其他账期，或用「自定义」选择首尾日期，也可看「全部时间」。开始、结束日期必填且开始不能晚于结束。

所有当前统计、明细、分类下钻及商户汇总共用同一范围；历史汇总按当前范围内的记录归入账期。只有账期模式显示上一完整账期环比，自定义和全部时间不显示环比。时间范围仅用于筛选，不写入交易。

## 日常记一笔

在首页、明细或导入页，点底部导航上方的「＋ 记一笔」，选择支出或收入、分类，用面板数字键盘输入金额，点「完成」。首页集中显示结余、支出和收入，并保留资产快照与账期核对入口。日期默认设备本地今天，可修改；商户/说明可选。金额必须大于0且最多两位小数，来源固定为「手动」。收入使用工资、退款 / 返款、转账收入、兼职 / 其他收入、其他这五种独立分类；收入不参与支出分类和 Top5。保存后面板关闭并显示反馈。「导入」页的次级入口使用同一个面板。

App 图标为柔和白底的极简美元符号 `$`，这只改变视觉标识；账单金额仍按原有人民币规则处理。图标源文件为 `icons/icon.svg`，192 / 512 PNG 均保留 maskable 裁切安全留白。

记录使用 `manual:` 加随机 UUID，日期保存为所选本地日期的 `YYYY-MM-DDT00:00:00`。所选分类保留，记账不会改变当前查看账期。明细、搜索、分类、趋势、大额支出和15日～14日账期统计直接复用现有逻辑。

在「交易列表」中点击任一记录，打开详情后可保存分类。有可靠交易对方的导入记录继续联动商户记忆；无对方或手动记录只改当前一笔。只有来源为「手动」的记录显示「删除」，确认后从本地存储移除并刷新统计。微信和支付宝记录不能通过此入口删除。输错时可删除后重新记一笔。

JSON 备份自动包含手动记录和核对字段。新备份增加 `snapshots`；旧备份缺少这一项时按空数组处理。恢复采取按 ID 合并，不主动删除现有无关记录或快照。

## 极简异常人工处理

微信、支付宝导入支出的状态含「退款」且尚未处理时，明细显示「需处理」及原始状态。「交易关闭」仍自动不计入，不强制处理收入或不计收支的退款。导入提示显示新增、重复跳过及全部时间的待处理数量；「查看需处理」直接打开全部时间的待处理明细，也可用「只看需处理」结合当前账期筛选。

点击交易打开详情，在「调整统计」中，可选择「正常计入」「不计入统计」，或输入大于0、不超过原始金额、最多两位小数的实际计入金额。普通导入支出也可主动调整；手动记账沿用删除后重录。原始金额、状态、来源保留，明细显示原金额及调整说明。

所有支出统计统一使用实际计入金额：排除或交易关闭的支出计为0，合法 `countedAmount` 替代原金额，否则使用原金额。被排除的记录不算支出笔数，但仍保留在明细记录数中。收入规则保持不变。

处理结果使用可选的 `excluded`、`countedAmount`、`reviewed` 字段保存，旧交易无需重写，备份会保留处理结果。

## 资产快照与账期核对

首页「资产快照」入口可新增、编辑和查看历史快照。输入日期、总资产、总负债、可选备注，实时显示净资产；金额为非负数，最多两位小数。快照保存 `id, date, totalAssets, totalLiabilities, netAssets, note, createdAt`，编辑保留身份和创建时间。点删除后必须在面板内再次确认，取消不删除；交易不受影响。

首页「账期核对」选择期初和期末快照，可使用首页当前范围、本账期或自定义范围，包含首尾两天；不允许用全部时间代替明确的核对区间。公式为「期初净资产 + 期间收入 − 期间支出 = 理论期末净资产」，差额为「实际期末 − 理论期末」。收支直接复用现有统计，包括退款调整、排除和已核对重复记录的规则。

核对差额仅用于辅助检查。同日工资到账、退款、转账时点、现金变化等情况也可能产生差额。快照的取样时点和统计区间由用户选择，不自动解释差额，也不自动改账。

## 导入对账

导入后若有候选，提示「发现 X 组疑似重复记录」并提供「去核对」。只比较来源为手动和来源非手动的两笔：收支方向相同、原始金额相同到分、日期相同或相差一天。分类和说明不作为确认依据。多个候选可能涉及同一笔，组数不是已确认重复笔数。

确认同一笔时，只在手动记录保存 `reconciledDuplicateOf`，正式记录和退款字段不改变。手动记录仍在明细，显示「已与导入记录核对，不计入统计」，但不再计入收入、支出、结余、分类、趋势、Top5及收支笔数。在详情中可撤销核对，恢复其原有统计规则。存储事务保证一对一，不能重复占用同一正式记录。

「不是同一笔」将正式记录 ID 保存到该手动记录的 `reconciliationDismissedIds`，刷新后不再提示该对；「暂不处理」只跳过本次面板展示，下次打开仍提示。两种持久化字段都随交易自动进入备份。没有仅凭日期金额的自动删除或自动确认。

## 数据升级与安全

升级到 v2 只增加快照表；不会 clear、重建数据库或更改旧交易稳定 ID、已有分类。若其他旧页面占用数据库，明确提示关闭其他记账页面后刷新；升级失败会报错，不以清空数据解决。新版连接在版本变化时主动关闭。

备份导出在同一只读事务中读取交易、记忆、快照；导入先校验，并在同一读写事务中恢复，非法快照或一对一关系冲突会整体拒绝，不部分覆盖现有数据。旧备份可恢复到空库；恢复到非空库时不会因为缺少快照字段而删除已有快照。

## 自动分类说明

分类按优先级工作：

1. **商户记忆**（最高）：你手动归过类的商户，直接套用
2. **支付宝原始分类**：支付宝账单自带"餐饮美食/交通出行"等，直接映射
3. **关键词规则**：按商户名/商品说明匹配（美团→餐饮、地铁→交通…）
4. **兜底**：都不命中 → 归入「其他」并高亮，等你手动归类

真实账单实测自动归类率约 **90%**。剩下的多是**人名往来**——这类无法靠规则预测，手动归一次即可被记住。

分类体系（学生版，10 类）：餐饮 / 交通 / 购物 / 学习教育 / 娱乐休闲 / 话费通讯 / 生活缴费 / 医疗健康 / 转账 / 其他。
（转账与红包统一归「转账」，便于把人对人的资金往来和真实消费分开看。）
想增改分类或关键词，编辑 `js/classify.js`。

本项目已部署在用户 fork 的 GitHub Pages：**https://xbing9698-ai.github.io/jizhang-app/**

**装到手机主屏**：手机浏览器（Chrome/Safari）打开上面网址 → 菜单「添加到主屏幕」→ 桌面出现「记账」图标，点开全屏运行，断网也能开。

```bash
git add -A && git commit -m "你的改动说明"
git push
```
GitHub Pages 会在 1-2 分钟内自动重新构建。

> 关键：所有资源都用相对路径（`./js/...`），因此在 Pages 的子路径 `/jizhang-app/` 下能正确加载——换任何托管（Netlify 等）也无需改路径。

## 更新代码后看不到变化？（重要）

本 App 用 Service Worker 做离线缓存，它会**缓存旧版代码**。如果你改了代码（比如分类规则）却发现没生效：

1. 改完后把 `sw.js` 里的 `const CACHE = 'jizhang-v4'` 版本号 +1（如 `v5`），重新部署 —— 这是最干净的办法
2. 或在浏览器：DevTools → Application → Service Workers → Unregister，再刷新
3. 手机上：关闭其他记账页面后重新打开，等待新版缓存生效。更新或数据库升级不需要清除网站数据；不要通过清缓存、卸载或重新导入全部历史账单来解决升级问题。日常可先导出备份。

## 开发

```bash
npm install       # 安装仅用于本地存储测试的开发依赖
node --test        # 跑纯逻辑单元测试（解析/去重/分类/统计）
npx serve .        # 本地起静态服务器预览（不要用 file:// 打开）
```

技术栈：HTML + 原生 JS(ES Module) + PapaParse(CSV) + SheetJS(xlsx) + Chart.js + IndexedDB。无构建步骤，改完刷新即生效。
